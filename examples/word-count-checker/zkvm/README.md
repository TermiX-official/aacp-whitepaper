# SP1 execution adapter

This adapter compiles the same counting core into a real SP1 RISC-V guest.
The runner uses SP1's **LightProver execution backend**, not a native fallback
or mock proof. Execution is not cryptographic proof generation or verification.
There is no network-prover mode, wallet, transaction, or paid service in this
runner. The SDK's network feature is disabled and no `.env` file is loaded.

## Versions and build

Use SP1 CLI/SDK **6.10.0** and its matching Succinct compiler
`succinct-1.96.0-64bit-v3`. SP1 6 uses
`riscv64im-succinct-zkvm-elf`; the parent repository's RISC-V32 instructions
describe an older SP1 generation. Existing SP1 v5 installations cannot build
this adapter without a matching v6 compiler. Native counting remains usable
without SP1.

Building the host SDK also requires the protobuf compiler `protoc` in `PATH`
(or its absolute path in `PROTOC`). This example does not install system tools
or modify an existing Rust toolchain automatically.

From `examples/word-count-checker/zkvm`:

```sh
cd program
cargo prove build --locked --output-directory ../elf
cd ..
cargo build --locked --manifest-path runner/Cargo.toml
python3 check.py runner/target/debug/aacp-word-count-sp1-runner \
  elf/aacp-word-count-guest
```

Initial dependency/toolchain downloads require internet access. The synthetic
checks execute locally afterward; no remote proving service is selected.
`check.py` requires Python 3 and checks actual ELF64/RISC-V machine headers.
It exports counts, hashes, instruction totals, and test outcomes to the ignored
`evidence.local.json`. It does not export document contents or local paths.

[`evidence.sample.json`](evidence.sample.json) records a local macOS ARM64 run
on 2026-11-28: seven guest executions and three host-side rejections passed.
The 20-word case executed 14,392 guest instructions. The ELF hash identifies
that particular build, not an independently authenticated program or proof.
Rebuild and rerun to produce evidence for your own compiler/host combination.

## Input binding and public output

The runner takes a local ELF path, an **expected ELF SHA-256**, and an
**expected document SHA-256**; raw document bytes arrive on stdin. It rejects
changed hashes before guest execution. In a real application those expected
hashes must come from the client's pinned job/program metadata, not from the
provider together with an arbitrary new document or executable.
These pins explicitly use SHA-256. An on-chain Keccak-256 identifier is a
different value and must not be substituted without an agreed hash format.

The synthetic check computes its own fixture/build hashes to exercise pinning;
that demonstration does not authenticate a job or establish external trust.
The guest receives one raw SP1 input frame, evaluates the document, computes
SHA-256 over the exact received bytes, and commits a 54-byte public journal:

| Offset | Bytes | Meaning |
| --- | --- | --- |
| 0 | 8 | ASCII `AACPWCV1` |
| 8 | 32 | SHA-256 of the raw document |
| 40 | 4 | Minimum words, little-endian u32 (20) |
| 44 | 4 | Maximum input bytes, little-endian u32 (65,536) |
| 48 | 4 | Observed words; zero for encoding/size errors |
| 52 | 1 | Accepted: 0 or 1 |
| 53 | 1 | Code: 0 accepted, 1 too short, 2 too large, 3 invalid UTF-8 |

The runner strictly decodes this journal and checks its document hash. SDK
execution success does not mean document acceptance: the guest terminates
normally for both verdicts, allowing either verdict to be committed. The
runner returns exit **0 for an accepted document and 1 for rejection/error**.
It does not enable SP1's experimental nonzero guest-exit proving mode.

## Resource and privacy limits

The runner limits the ELF to 16 MiB, input to 65,537 bytes, and execution to
200 million SP1 clock cycles. The extra input byte allows exercising a
document-size rejection inside the guest. Longer inputs are rejected by the
host before execution. The guest also checks its frame length; SP1's input
allocator reads a prover-controlled frame **before** that guest check. A custom
host must therefore enforce its own framing/memory limits; this is not a claim
that arbitrary malicious frames can never allocate memory. SP1 instruction
reporting is enabled with the SDK gas-calculation option;
this is local computation metering, not a blockchain payment. The test
harness also applies subprocess timeouts.

Only synthetic/non-sensitive documents should be used in public examples.
Hashes and word counts can reveal information about guessable documents.
No document bytes are printed, but this example is not a confidentiality layer.

## Remaining boundaries

No proof has been generated by this runner. It cannot authorize escrow
settlement, establish a TEE attestation, or prove buyer acceptance. An eventual
proof-consuming integration must verify the proof against the client's pinned
program verification key, bind the public input hash and policy to the job,
and check the accepted flag. It must reject invalid hints, execution failures,
malformed journals, and mismatched inputs. Never substitute native execution
for an unavailable zkVM or treat execution evidence as a verified proof.
